「运行环境」页管理服务运行所依赖的推理引擎：llama.cpp 主程序（llama-server）以及 Windows 上随 CUDA 构建一起安装的 CUDA 运行时（cudart）。

## 状态与组件

页面以卡片形式展示 llama.cpp 的信息：

- **状态**：已安装 / 未找到；
- **版本**：已安装时显示探测到的版本号；
- **安装路径 / 下载路径**：主程序所在目录和新下载内容的落点；
- **组件列表**（已安装时显示）：
  - `llama-server 主程序`：推理服务的本体；
  - `CUDA 运行时 (cudart)`：仅在 Windows 上显示，标注检测到的 CUDA 大版本（如 `CUDA 12`）。它随 CUDA 构建的 llama.cpp 自动下载，没有它，NVIDIA 显卡加速无法工作。

## 下载 llama.cpp

未安装时，页面提供两个入口：

- **下载 llama.cpp**：自动从 GitHub Release 获取最新版本，一次下载两个包——主程序包和 CUDA 运行时包（Windows），分别显示进度条；
- **自定义**：浏览选择一个已有的 llama.cpp 目录，应用会改用它而不再下载。

下载过程中可以随时**暂停**、**继续**（断点续传，不会从头开始）或**取消**。网络抖动导致的临时失败会自动重试（最多 3 次，每次间隔 3 秒）；彻底失败后页面会显示原因，并提供重试按钮。

## 自定义目录

点「自定义」选择目录后，应用立即重新探测该目录：

- 目录里需要有 llama-server 主程序；CUDA 构建还需要对应的 cudart 动态库在同一目录（或系统 PATH）中。
- 选择结果会持久保存，之后每次启动都使用这个目录。

下载路径本身可以在「偏好设置 → 目录」中修改，决定新下载的 llama.cpp 安装到哪里。

## CUDA 兼容性三态显示

「系统信息」页的 CUDA 卡片中有一行「CUDA 兼容性」，用三种状态说明你的显卡与 CUDA 运行时是否匹配：

| 状态 | 含义 |
| --- | --- |
| 兼容 | 常规显卡（计算能力低于 12.0），当前 CUDA 运行时即可正常工作 |
| 需 CUDA ≥12.8 | 显卡是 Blackwell 架构（RTX 50 系，计算能力 ≥ 12.0），但当前 CUDA 运行时未被证实满足 12.8 |
| 已满足 | Blackwell 显卡，且已安装的 CUDA 运行时确认满足 12.8 |

为什么有「需 CUDA ≥12.8」这一档：Blackwell 显卡要求 CUDA 12.8 及以上，否则 llama-server 会报 `no kernel image` 无法启动。而 cudart 的版本号只能从动态库文件名解析出大版本（如 `12`），无法证明小版本达标，所以只要不能明确证明满足 12.8，就会保守地提示「需 CUDA ≥12.8」。遇到这个提示时，重新在「运行环境」页下载最新版 llama.cpp（自带的 cudart 满足要求），或安装 CUDA 13 系列运行时即可。
