「API 路由模式」（无头模式）让应用变成一个纯后台服务：**关闭图形界面，只保留系统托盘和 llama-server**，继续对外提供 OpenAI 兼容接口。适合把这台机器当作家庭/工作室的常驻推理服务器。

## 开启与关闭

- **开启**：在「偏好设置」页的「API 路由模式」行打开开关。应用会自动重启并进入无头模式，图形界面随即关闭；
- **返回界面**：右下角托盘图标右键 → 「显示主窗口」，应用会再次自动重启并回到完整界面。

两个前提条件：

- 仅 **Windows** 支持；
- 必须先开启**系统托盘**——托盘菜单是无头模式下回到界面的唯一入口；
- 开发者注意：`wails3 task dev` 开发模式下此功能不可用（切换会重启进程、终止开发会话），请使用正式构建的应用测试。

## GUI 与无头之间切换不断流

模型加载动辄几十秒，如果切换模式时把服务一起重启，正在使用 API 的客户端就会中断。应用为此设计了**交接机制**：

1. 切换模式时，当前进程把**仍在运行的 llama-server** 的身份（进程 ID、端口、日志路径）写入一个交接记录文件；
2. 当前进程退出，新进程启动后探测这份记录，确认那台服务仍然健康（端口有响应、进程存活）后直接**认领**它，而不是启动新的；
3. 整个过程中 llama-server 从未停止——**模型不重新加载，API 调用不中断**，只是换了宿主进程。

认领后，服务的日志会继续被新进程采集，监控页的 Token 速度等指标照常工作。如果交接记录过期或服务已死，应用会退回全新启动，不会误接管无关进程。

## 无头模式下的行为

- 系统托盘常驻，托盘菜单提供「显示主窗口」和退出入口；
- llama-server 在后台持续服务，下载任务也会从持久化队列恢复继续；
- 没有图形界面可以显示错误——如果无头模式下 llama-server 启动失败，会弹出**系统原生弹窗**提示，应用本身保持运行，保证托盘回路可用；
- 再次从托盘返回界面后，服务依然无缝接管，一切照旧。

## 什么场景适合无头模式

- 机器主要当推理服务器用，很少看界面；
- 想在开机后常驻后台，给局域网里的其他设备提供 API（记得在设置里把访问范围改为局域网并配置 API Key）；
- 不想让应用窗口占用任务栏。
